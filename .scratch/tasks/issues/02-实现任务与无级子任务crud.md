# 实现任务与无级子任务 CRUD

## 用户故事

作为用户，我希望创建任务和嵌套子任务，以便将工作拆分到任意深度。

## 范围

### 包含
- 实现任务的创建、读取、更新、删除（CRUD）接口
- 支持通过 `parentId` 创建嵌套子任务，表达无级层级关系
- 读取任务时返回层级结构
- 任务创建时初始化 `version` 字段

### 不包含
- 任务移动、完成、恢复等状态变更
- 乐观并发控制逻辑
- 提醒（reminder）与分配（assign）相关功能
- 通知创建与投递

## 验收标准

### 场景 1：创建任务

Given 已认证用户
When 用户 POST 一个任务到列表
Then 任务被创建并带有 version

### 场景 2：创建嵌套子任务

Given 一个已存在的任务
When 用户 POST 一个带有 parentId 的子任务
Then 子任务被关联到父任务

### 场景 3：读取任务层级

Given 任务包含嵌套子任务
When 用户获取该任务
Then 返回任务层级结构

## Agent Brief

**Category:** enhancement
**Summary:** 实现 tasks Lambda 的任务 CRUD 与无级子任务：创建（含 parentId 嵌套）、列表分页查询、单任务层级树读取、带乐观并发的更新与简化软删除

**Current behavior:**
`apps/api` 只有 health/lists/users/verify 四个域，无任何 tasks 实现与路由。`packages/shared` 已有完整 task schema（`taskInputSchema`/`taskUpdateSchema`/`taskSchema`，含 `parentId`、`assigneeIds`、`priority`、`dueDate` 等全部字段）和 cursor/response/validate 工具。DynamoDB 单表 `LycoTable` 与 GSI1 已在 SST 中就绪（008 产物）。

**Desired behavior:**
参照 008 lists 的已实现模式（repository + handler 分层、条件写、错误映射）实现 5 个端点：

| 端点 | 行为 |
|---|---|
| `POST /api/tasks` | 创建任务，`version=1` + 审计字段（`createdBy`/`updatedBy` 取 JWT `sub`）。`parentId` 存在时校验父任务存在（不存在 → 404），`listId` 从父任务派生覆盖客户端值。`assigneeIds` 仅作普通属性存储，不触发任何通知 |
| `GET /api/tasks?listId=` | `listId` 必填（缺省 → 400 `VALIDATION_ERROR`）。返回该列表未删除任务的平铺分页：`limit` 默认 50 最大 100，不透明 `nextCursor` |
| `GET /api/tasks/{id}` | 返回任务本体 + 递归嵌套 `children` 树（只含未删除子任务，按 `order` 排序）。任务不存在或已删除 → 404 |
| `PATCH /api/tasks/{id}` | body 携带 `expectedVersion`。可改 `title/notes/assigneeIds/isFlagged/priority/dueDate/dueTime/timeZone/recurrence/order`；**不可**改 `listId/parentId/isCompleted`（属 010）。版本不匹配或目标已删除 → 409 `CONFLICT`；不存在 → 404 |
| `DELETE /api/tasks/{id}` | query 携带 `expectedVersion`（同 008 DELETE lists）。简化软删除：写 `deletedAt` + version 递增。有子任务时允许删除，子任务保留原样。版本冲突或已删除 → 409；不存在 → 404 |

**Key interfaces:**
- DynamoDB 键设计（设计文档权威）：`PK=TASK#<taskId>`、`SK=METADATA`、`GSI1PK=TASKS`、`GSI1SK=LIST#<listId>#PARENT#<parentId|ROOT>#ORDER#<orderKey>#TASK#<taskId>`；实体可通过自身 ID 直接 GetItem，子任务只靠 `parentId` 表达层级
- 复用 `packages/shared` 的 task schema、cursor 编解码、`buildResponse`/`errorResponse`、`parseRequest`；如发现 schema 缺口（如 tasks 查询参数 schema），在 shared 中补充并配测试
- 复用 008 的分层模式：`client.ts`（DynamoDB document client）、`db.ts`（repository，`NotFoundError`/`ConflictError`）、`index.ts`（路由 + 错误映射）
- SST：tasks Lambda 绑定 5 条路由（含 `ANY /api/tasks/{proxy+}`），注入 `TABLE_NAME`，最小 DynamoDB 权限，JWT 授权

**Acceptance criteria:**

- [ ] `GET /api/tasks?listId=` 分页正确，已软删除任务不出现在结果中；缺 `listId` 返回 400
