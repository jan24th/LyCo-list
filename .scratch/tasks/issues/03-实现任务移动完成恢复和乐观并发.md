# 实现任务移动、完成、恢复和乐观并发

## 用户故事

作为用户，我希望移动、完成和恢复任务，并检测冲突，以便跨设备安全地修改任务。

## 范围

### 包含
- 实现任务在列表之间的移动
- 实现任务完成状态切换并记录完成时间戳
- 实现已完成任务恢复为活跃状态
- 实现基于 `expectedVersion` 的乐观并发控制

### 不包含
- 任务与子任务的基础 CRUD
- 任务分配与通知创建
- 提醒 CRUD 与到期处理

## 验收标准

### 场景 1：移动任务到另一个列表

Given 列表 A 中有一个任务
When 用户将其移动到列表 B
Then 任务属于列表 B

### 场景 2：完成任务

Given 一个活跃的任务
When 用户将其标记为完成
Then 任务被完成并记录时间戳

### 场景 3：恢复已完成的任务

Given 一个已完成的任务
When 用户恢复它
Then 任务重新变为活跃状态

### 场景 4：乐观并发冲突

Given 任务 version 为 2
When 发送 expectedVersion 为 1 的更新
Then API 返回 409

1. **“恢复”语义** = 恢复已完成任务（场景 3），不是撤销删除。撤销删除（`undoUntil`/`DELETION_JOB`）在 009 triage 已裁定归 018，本次不动 DELETE 端点。
2. **重复任务完成**：完成 `recurrence != none` 的任务需要写 `lastCompletedAt` + 按本地日历推进 dueDate/提醒，推进逻辑属 011。本期对重复任务 complete 返回 400（`VALIDATION_ERROR`，“重复任务暂不支持完成”），011 再放开。
3. **move 循环防护**：不能把任务移动到自身或自身后代下，违反返回 400。
4. **move 的 listId 一致性**：`parentId` 非空时目标 listId 以父任务所在 listId 为准（沿用 createTask 先例）；输入 listId 与父任务不符返回 400。
5. **后代级联**：移动父任务时所有后代 `listId` 级联重写（GSI1SK 含 listId，必须逐条重写），后代 version+1、更新审计字段。不做事务：父任务条件写成功后级联，中途失败记 `console.error`（MVP 接受，与 018 cleanup 兜底的设计精神一致）。
6. **重复 complete / 对未完成任务 restore**：设计未规定报错，允许（version 照常递增），幂等性由 expectedVersion 保证。

### Plan

1. **db.ts `completeTask`** → 测试先行：`getTaskById` 不存在 → NotFoundError；`recurrence != none` → ValidationError（裁定 2）；条件写 `version = :expectedVersion AND attribute_not_exists(deletedAt)`，SET `completedAt = :now`、version+1、updatedAt/updatedBy；冲突 → ConflictError。用 UpdateCommand + ReturnValues ALL_NEW（仿 deleteTask）
2. **db.ts `restoreTask`** → 同上，SET `completedAt = null`（REMOVE 或 SET null，与 schema `nullable` 一致用 SET :null）
3. **db.ts `moveTask`** → 测试先行：自身/后代 parentId → ValidationError（裁定 3，需遍历祖先链或后代集）；parentId 非空 → 父任务必须存在且 listId 一致（裁定 4）；条件写更新 listId/parentId/order + GSI keys；成功后递归级联后代（queryDirectChildren 复用），后代逐条 Put 新 GSI + version+1
4. **index.ts 路由** → 三个 `POST /api/tasks/{id}/{complete,restore,move}` 分支，body 校验（complete/restore 只需 `{ expectedVersion }`，move 用 `moveTaskInputSchema`），ValidationError → 400
5. **shared schema** → complete/restore body schema（`z.object({ expectedVersion })`，可复用现有模式）
6. **Bruno** → `bruno/lyco-list/tasks/` 补 `complete task.bru`、`move task.bru`、`restore task.bru`（仿现有文件格式）
